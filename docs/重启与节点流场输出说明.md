# 重启文件与节点流场输出说明（2026-09-23 新增）

> 代码：`src/sub_restart.f90`（重启读写 + 自调度）、`src/sub_IO.f90`（`output_flow_node`）
> 开关：`control.ec` → `$flow_ec`（旧组 `$control_ec` 同样可用）

## 1. 功能一览

| 功能 | 文件 | 开关 | 默认 |
|---|---|---|---|
| 重启（续算） | `field_restart.dat` | `Iflag_restart` | `0` = 存在即自动续算（`1` 强制、`-1` 既不读也不写=完全关闭） |
| 重启写出间隔 | — | `Kstep_restart` | `0` = 同 `Kstep_save` |
| 节点/SI 流场输出 | `flow3d_node.dat` | `Iflag_flow_node` | `0` = 关 |

```
$flow_ec
  Iflag_restart=0     ! 0=存在 field_restart.dat 即自动续算  1=强制续算(无文件报错退出)  -1=完全关闭(不读不写)
  Kstep_restart=0     ! 重启文件写出间隔(<=0 时用 Kstep_save)
  Iflag_flow_node=0   ! 1=额外写节点值+SI+无格式流场 flow3d_node.dat
$end
```

## 2. 重启文件 `field_restart.dat`

**内容**（unformatted，逐记录含块头；全局块序 = `flow3d.dat` / `Mesh3d.x` 的块序）：

```
记录1 : iver, Total_block, Num_Mesh, NVAR, Kstep, LAP
记录2 : tt, Ma, Re, gamma, T_inf, Lscale, dt_global
每个 block：
  记录 : nx, ny, nz
  记录 : U (1:NVAR, 1-LAP:nx+LAP-1, 1-LAP:ny+LAP-1, 1-LAP:nz+LAP-1)
  记录 : Ts   (同上范围)     固体/多孔骨架温度
  记录 : Tsn  (同上范围)     上一时间步的 Ts
  记录 : p    (同上范围)     低速/多孔压力
```

- **包含缓冲区（ghost / buffer）信息**：写入的是**完整 LAP=4 层鬼点盒**，因此高精度
  格式所需的缓冲信息在续算时被精确恢复；读入后还会再刷新一次**块间**缓冲
  （`update_buffer_onemesh` / `update_Ts_buffer_onemesh`），所以即使中途改过边界/网格连接也安全。
- **保存计算步数与时间**：`Kstep`、`tt` 存在头记录里；续算时写回 `Mesh(1)%Kstep/tt`。
- **定期保存**：默认与 `Kstep_save` 同节奏；可用 `Kstep_restart` 单独设定。
- **自动续算**：启动时若存在可用文件即自动接管（`Iflag_restart=0`），
  不存在或与算例不符（块数/NVAR/维数不一致）则回退到原来的初始化
  （均匀场 / `Iflag_init>0` 读 `flow3d.dat`）；`Iflag_restart=1` 时不可用即报错 `stop 1`。
- 交错耦合模式（`Iflag_Couple_Scheme=1`）下：三个驱动入口的 `tt/Kstep` 归零已改为
  “有重启则恢复”，并在每轮气体段的保存点与运行结束处写出重启文件；
  界面量（`fp_Tw/fp_u`）仍从 `control.ec` 的初值播种，由外层迭代再收敛（已打印提示）。
- 体积参考：`cases/fluid_solid/run_case1_solid`（2 块，67×101×2 + 101×201×2）≈ **17.5 MB/次**。

## 3. 节点流场输出 `flow3d_node.dat`

- **节点值**：把格心量用标准 8 格心算术平均插值到网格节点（`i=1..nx, j=1..ny, k=1..nz`），
  与 `util/readflow3d-ver2.x` 的 `comput_value_in_mesh` 完全同一公式。
- **单位**：**SI**。可压块按来流参考态换算
  （`U_ref=Ma·a_ref`，`rho_ref=Re·μ_SI(T_inf)/(Ma·a_ref·Lscale)`，`T_ref=T_inf`）；
  低速/多孔块本身存 SI（kg/m³、m/s、K）不再缩放。
- **无格式 + 可与 `Mesh3d.x` 组合**：unformatted，**逐块一条记录**，块序 = `Mesh3d.x` 块序，
  每条记录含 `d,u,v,w,T`（固体块按 `flow3d.vtk` 约定 `d=u=v=w=0, T=Ts[K]`，块数始终与网格一致）。
  因此可用 PLOT3D 读法把 `Mesh3d.x`（网格）与本文件（结果）组合显示。
- 维度自检：`nx·ny·nz` 与 `Mesh3d.x` 完全一致（实测 51×9×9=4131；67×101×2=13534；101×201×2=40602）。
- 体积参考：case1 ≈ **2.2 MB/次**。

### 用 python 自检（示例）
```python
import struct
rc = lambda f: (lambda n: (f.read(n), f.read(4)))(struct.unpack('<I', f.read(4))[0])
# 读 Mesh3d.x 的第 1、2 条记录可得 nblock 与各块 (ni,nj,nk)，
# 再按 5*ni*nj*nk 个 double 逐块读 flow3d_node.dat 即可（/tmp/verify_node.py 即此逻辑）
```

## 7. 实现要点（备忘）

- 写/读都采用与 `output_flow` / `read_flow_data` 相同的约定：**0 号进程持文件**，
  按**全局块序**处理；远端块由属主进程用 `tag = 本地块号 + 200/300` 收发；
  **非 0 号进程只遍历自己拥有的块**（`B_n(m)` 只在本进程有效，越界访问会导致挂死——已修）。
- 调度集中在 `restart_step_output(nMesh)`：内部按 `Kstep_restart`/`Kstep_save` 判 due，
  因此主循环与三个交错驱动都只需一行调用，且必须**由所有 rank 调用**（函数内部做 MPI）。
- `.gitignore` 已忽略 `cases/**/field_restart.dat`、`cases/**/flow3d_node.dat`。
