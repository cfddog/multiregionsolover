## 作业提交（Slurm）

- 官方帮助（命令/脚本模板/常用命令）：
  <https://www.scnet.cn/help/docs/mainsite/hpc/cmd/slurm/>
- 现成模板在**集群** `~/sundong/run.slurm`
  （= `/work/home/lijunyang/sundong/run.slurm`，261 B，2026-10-18 读取）：
  **用到哪个目录就拷到哪个目录**，改 `-n`（核数）/`-J`（作业名），
  然后在**该目录**执行 `sbatch run.slurm`；日志默认 `MixSolver_out.log` / `MixSolver_err.log`
  （可用 `-o/-e` 改名）。
  **注意：本仓库本地根目录没有 `run.slurm`**，这个模板只存在于集群侧。

```bash
#!/bin/bash
#SBATCH -p wzacnormal   # 队列
#SBATCH -N 1
#SBATCH -n 1            # 核数
#SBATCH -J MixSolver
#SBATCH -o MixSolver_out.log
#SBATCH -e MixSolver_err.log

export PATH=/work/home/lijunyang/sundong/MixSolver/MixSolver/bin:$PATH

mpirun -n 1 ../../bin/mixnsolver
```

- 逐行含义：`-p` 分区（模板用 `wzacnormal`；普通计算也可 `wzhcnormal`）、`-N` 节点数、
  `-n` 任务数、`-J` 作业名、`-o/-e` 标准输出/错误日志。
- **跑本仓库时要改两处**：① `export PATH=...MixSolver/MixSolver/bin` 是那个项目自带的，
  可删；② `mpirun -n 1 ../../bin/mixnsolver` → `mpirun -n <np> ../../bin/MultiPhysMixSolver`
  （算例目录在 `cases/<case>/` 时，`../../bin/` 正好指到仓库的 `bin/`）。
- 常用命令：`sbatch run.slurm` 提交、`squeue -u lijunyang` 看队列、`scancel <jobid>` 取消、
  `sinfo -s` 看分区空闲、`sacct -j <jobid>` 看历史。
- 提醒：`/work` 已用 93%，作业产物（`flow3d.vtk`、`field_restart.dat`、单文件 VTK）
  别长期堆；`partation.dat` 是**本地运行**用的分块表，提交作业前按 np 生成、别乱拷。

## 踩坑记录（集群/脚本）

1. **`sed ... > np1/control.ec` 会截断软链目标**：`np1/control.ec` 原本软链到 `../control.ec`，
   重定向先把目标清空再读 ⇒ 仓库 `control.ec` 一度变 0 字节（已 `git checkout` 恢复）。
   `prep.sh` 现为先 `rm -f`、写 `control.ec.tmp`、再 `mv`。
2. **运行目录多一层**：`cases/<case>/np*/` 到仓库根是三级，二进制应为
   `../../../bin/MultiPhysMixSolver`（不是 `../../bin/`）。写错时 `mpirun` 报
   `unable to launch ... could not access or execute an executable`；`run.slurm` 已用
   `cd ../../..` 定位并检查可执行位。
3. `sbatch -n` 必须与该目录 `partation.dat` 的进程数一致，否则 MPI 通信域与分块表不匹配。
